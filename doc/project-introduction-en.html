01 / Purpose and responsibilities

PII-Detect-Engine is a standalone Python HTTP service that identifies personal information, identity documents, accounts, and secrets in text. It returns entity types, original-text offsets, scores, and detection sources so the upstream gateway can decide whether data may leave the system and how sensitive values should be replaced.

3 detection layers

Independent switches for rules, Presidio, and GLiNER2.

en + zh

English and Chinese spaCy models through Presidio.

FastAPI :8000

Analysis and health-check endpoints.

Service boundary: Python performs detection. Redaction, policy blocking, token vaults, external business-model calls, and database auditing belong to the adjacent C# gateway. This project has no model-training or fine-tuning pipeline.

03 / Startup and request lifecycle

FastAPI lifespan executes Detector(load_config()) at startup. After configuration validation, only enabled engines are instantiated. Model instances are reused within the process. Disabling Presidio / GLiNER2 avoids importing its optional third-party package and loading its model.

for engine in (self.rules, self.presidio, self.gliner):
    if engine is not None:
        found.extend(engine.analyze(request))
  • The layers run sequentially for one text. Every layer receives the same original text; no intermediate redaction is performed.
  • A finding does not short-circuit subsequent layers. Disabled components are skipped.
  • include_ner=false skips GLiNER2 inference for one request; it does not disable Presidio or unload weights.
  • Different HTTP requests may be scheduled in FastAPI's thread pool. There is no custom inference-concurrency limit, model lock, or job queue. C# message-level concurrency is a separate concern.
  • There is no batch-analysis endpoint, streaming entity output, or explicit long-document chunking. Findings return together after merging.

04 / Rules: patterns and structural validation

rules.py contains 12 patterns across 8 output types. Each pattern defines a type, compiled expression, and fixed heuristic score. These scores are not measured accuracy.

TypeCoverage and limits
emailEmail format.
phoneGeneric separated phone numbers and compact mainland mobile numbers, with optional 86 / +86 prefix.
credit_card13–19 digit candidates; no Luhn validation.
ip_addressIPv4 candidates; octets are not checked against 0–255.
credentialPassword, API key, secret, and private-key assignments. Spans include the field name and its value.
us_ssnConsistent hyphen/space forms. Compact digits require SSN context. Invalid areas, group 00, and serial 0000 are rejected.
identity_numberChinese 18-digit IDs: province prefix, nonzero locality suffix, real non-future birth date, nonzero sequence, MOD 11-2 checksum, and X/x support. Legacy 15-digit IDs require document context, use 19xx birth years, and have no checksum.
passportMainland ordinary passports: G/E + 8 digits, or E + letter + 7 digits. Other 6–9 character alphanumeric candidates require passport context and at least one digit.

contextual_pattern() uses a named value group to exclude document labels and JSON quotes from returned offsets. The standalone mainland passport pattern excludes I/O in the second letter position. The generic context pattern is not strict country-specific passport validation.

Identical type/span findings retain the highest score. Recognized IDs, SSNs, and passports take precedence over overlapping generic phone/card results within this engine. Full historical county codes are not verified. Passing format/checksum validation does not prove document issuance.

05 / Presidio: bilingual NLP and recognizers

presidio.py adapts the recognizer framework to shared entity objects. Startup reads presidio-config.json and checks installed model packages with spacy.util.is_package(). Missing packages generate warnings and disable that language without an automatic download.

  • Models are en_core_web_lg for English and zh_core_web_sm for Chinese.
  • The adapter preserves existing NLP mappings and ignores ORGANIZATION and other excluded tags. General name/location recognition is not a specialized Chinese PII model; complete street addresses need separate evaluation.
  • For zh it registers email, phone, payment card, IBAN, IP, MAC, URL, and crypto recognizers with Simplified/Traditional Chinese context. Phone regions are CN / HK / TW.
  • analyzer.analyze(text, language) receives no entity allowlist or custom score threshold. It uses registered types for the selected language and engine-default behavior.
  • PRESIDIO_TYPE_MAP only renames outputs: EMAIL_ADDRESS → email and US_SSN → us_ssn. Unmapped names become lowercase. LOCATION currently becomes address; that does not imply full-address coverage.
  • Initialization exceptions are logged and make this engine unavailable. Analysis exceptions are logged and return findings collected so far, usually none. A single response does not explicitly distinguish layer failure from no findings.

The preceding registry inspection found 19 English and 13 Chinese types. Registration does not establish accuracy. Model values are installed package names; arbitrary local model directories are not supported by this preflight. See the Presidio label reference.

06 / GLiNER2: local label-conditioned extraction

gliner.py uses fastino/gliner2-privacy-filter-PII-multi, sending text and ENTITY_LABELS together to predict spans from context.

result = self.model.extract_entities(
    request.text, ENTITY_LABELS, threshold=GLINER_THRESHOLD,
    include_confidence=True, include_spans=True,
)
  • The code configures 29 labels; the checkpoint documents 42. Labels remain in code, without a per-label configuration file.
  • A missing dependency or model directory makes the layer unavailable. Failure loading an existing directory propagates and may prevent startup.
  • The default threshold is 0.65. Conversion accepts dictionary results with integer start/end. Scores use confidence, then score, then 0.0.
  • This adapter does not validate input-span bounds; the C# gateway adds checks. Inference errors propagate and fail the request.
  • The local configuration identifies microsoft/mdeberta-v3-base, model_type=extractor, and max_width=8. The latter is an internal span setting, not the HTTP character limit.
  • Weights occupy approximately 1.23 GB. Runtime memory, latency, and Chinese accuracy have not been systematically evaluated. The documented training languages exclude Chinese; Chinese Presidio tests do not validate GLiNER2.

07 / HTTP API, entity contract, and merging

Endpoint / fieldBehavior
POST /analyzeAccepts text, language, and include_ner; returns entities and engine.

text1–50,000 Python characters, not a model-token limit.

Example request:

{
  "text": "邮箱 alice@example.com",
  "language": "zh",
  "include_ner": false
}

Illustrative rules-only response; findings and status can differ when all default engines are enabled:

{
  "entities": [
    {"type": "email", "start": 3, "end": 20, "score": 0.99, "source": "rule"}
  ],
  "engine": {"rules": true, "presidio": false, "gliner": false, "offline_mode": true}
}

Entity start/end offsets count Python Unicode code points: start inclusive, end exclusive, matching text[start:end]. source is rule / presidio / gliner. Normal responses do not separately return the sensitive substring.

The orchestrator deduplicates by (type, start, end), retains the highest score for exact matches, and sorts by start/end. Overlaps with different types or boundaries usually remain. Aliases such as phone / phone_number and credit_card / card_number are not fully normalized.

Fixed rule scores, Presidio rule/context scores, and GLiNER2 model scores are not calibrated across sources, limiting direct highest-score comparison. Invalid requests normally receive HTTP 422. Unhandled inference exceptions fail the request.

08 / Configuration and deployment

Engine switches in config.json:

{"rules": true, "presidio": true, "gliner": true}

Models in presidio-config.json:

{"models": {"en": "en_core_web_lg", "zh": "zh_core_web_sm"}}
  • All three switches are required JSON booleans. Unknown keys, string booleans, and missing fields fail validation. Presidio model keys are restricted to en/zh, with at least one entry.
  • Both files resolve relative to the project and load at startup; no hot reload exists. Presidio configuration is read only when that engine is enabled.
  • GLINER_MODEL_PATH defaults to the project models directory. Relative environment overrides resolve against the process working directory.
  • GLINER_THRESHOLD defaults to 0.65 and is parsed as float at import without explicit 0–1 range validation.
  • OFFLINE_MODE defaults to true. It reports a flag rather than enforcing network isolation.
  • Disabling every layer returns no entities, which the gateway interprets as no detected PII. Service configuration differs from config.json inside the model directory.

start.ps1 creates the environment, upgrades pip, installs all dependencies, and starts the service; it therefore includes online preparation. install_presidio_models.py explicitly installs missing spaCy packages; download_model.py explicitly downloads a Hugging Face snapshot. Once prepared, direct Uvicorn startup supports local inference.

Dependencies include FastAPI, Uvicorn, Presidio, GLiNER2, Transformers, Hugging Face Hub, and Protobuf; ranges are in requirements.txt. There is no complete lock file or pinned Hub revision, so reproducibility needs additional version management.

09 / Collaboration with the C# gateway

Select language
→

→
Convert UTF-16 offsets
→
Policy, redaction, provider

The adjacent PiiText.cs supports auto / en / zh. Auto chooses zh for any Han character and en otherwise; it is not full language identification. The gateway calls the detector per message and uses Task.WhenAll for message-level concurrency. Request language affects Presidio; the other engines still receive the original text.

Security.cs converts Python code-point offsets to C# UTF-16 offsets before extraction and replacement, avoiding shifts around emoji and supplementary Han. Invalid ranges reject the detection response. The gateway handles overlaps, risk levels, allow/redact/block, placeholder mappings, restoration, and auditing.

Provider responses are scanned after return. Newly generated PII currently produces a response_flagged audit marker without automatic further redaction or blocking. Python does not maintain these business states.

11 / Limits and recommended evolution

AreaLimit and recommendation
Failure semanticsPresidio fallback can resemble no findings, while GLiNER2 can fail the request. Add per-request engine status and policies requiring successful detection.
Types and scoresAliases remain and scores lack calibration. Normalize types and evaluate source priorities and thresholds.
ConcurrencySequential layers coexist with concurrent messages and shared models. Measure correctness, latency, and throughput before bounded parallelism or batching.
Chinese qualityGeneral small NER does not guarantee complete addresses or Traditional Chinese names. Build Simplified, Traditional, and mixed-language evaluation sets.
Length and validationThe character limit differs from model windows. Add overlapping chunks, global offset restoration, and stronger IP/card validation.
Configuration and operationsNo per-type switches or thresholds; Python has no authentication, rate limiting, metrics, or persistence. Add deployment-appropriate access control, observability, and version pinning.

These are proposals; business logic was not changed while generating this document. Further reading: GLiNER2 labels · Presidio labels · README.
