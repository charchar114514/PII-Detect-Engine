01 / 项目定位与职责

PII-Detect-Engine 是独立的 Python HTTP 服务，识别输入中的个人信息、证件、账户及秘密凭据。返回结果包括类型、原文起止位置、分数和检测来源，供上层网关决定是否允许外发以及如何替换敏感内容。

3 层检测

正则、Presidio、GLiNER2 可以独立启停。

en + zh

Presidio 接入英文与中文 spaCy 模型。

FastAPI :8000

提供分析和健康检查接口。

职责边界：Python 服务负责检测，不实现脱敏、策略拦截、Token Vault、外部业务模型调用或数据库审计。这些能力由相邻的 C# 网关实现。项目没有模型训练或微调流程。

03 / 启动与请求工作流

FastAPI 的 lifespan 在启动时执行 Detector(load_config())。配置文件校验通过后，只创建已启用的引擎，模型实例在进程内复用；关闭 Presidio / GLiNER2 时，不导入相应第三方包或加载权重。

校验请求
→
正则
→
Presidio
→
GLiNER2
→
合并并返回
for engine in (self.rules, self.presidio, self.gliner):
    if engine is not None:
        found.extend(engine.analyze(request))
  • 同一文本的三个组件串行执行，每层都接收相同原文，不会先脱敏再传给下一层。
  • 前一层命中不触发提前结束；关闭的组件跳过。
  • include_ner=false 仅跳过单次 GLiNER2 推理，不影响 Presidio，也不卸载已加载权重。
  • 不同 HTTP 请求可能由 FastAPI 线程池调度；目前没有自定义推理并发上限、模型锁或任务队列。C# 同时提交多条消息属于另一层并发。
  • 没有批量分析接口、流式实体输出或显式长文本分块。所有结果汇总后一次返回。

04 / 正则引擎：规则与结构校验

rules.py 当前包含 12 条模式、8 个输出类型。每条模式由类型、编译后的表达式和固定分数组成；分数是人工经验值，不代表统计准确率。

类型覆盖与限制
email邮箱格式。
phone通用分隔式电话及中国大陆连续手机号，可带 86 / +86 前缀。
credit_card13～19 位数字候选，尚无 Luhn 校验。
ip_addressIPv4 候选，尚未校验每段的 0～255 范围。
credential密码、API key、secret、private key 等赋值文本；匹配范围包含字段名及其值。
us_ssn连字符或空格形式；纯数字形式要求 SSN 上下文。排除无效开头、00 组号和 0000 序列号。
identity_number18 位中国身份证：省级前缀、非零地区后缀、真实且非未来生日、非零顺序码、MOD 11-2 校验位，支持 X/x；旧版 15 位须带身份证上下文，生日按 19xx 年解析，无校验位。
passport中国普通护照 G/E + 8 位数字、E + 字母 + 7 位数字；其他 6～9 位字母数字候选要求护照上下文且至少一个数字。

contextual_pattern() 使用名为 value 的捕获组，令返回位置只包含号码，排除“护照号”等提示词及 JSON 引号。普通护照独立模式第二位字母排除 I/O；通用上下文模式并不是某个国家的严格护照验证。

同类型同跨度保留最高分；已识别的身份证、SSN、护照优先于与其重叠的宽泛电话和银行卡结果。身份证未核验完整历史县级区划码，格式和校验位通过不证明证件已真实签发。

05 / Presidio：双语 NLP 与识别器

presidio.py 将识别器框架接入统一实体结构。初始化时读取 presidio-config.json，通过 spacy.util.is_package() 检查已安装的模型包；缺失模型会告警并禁用该语言，启动时不自动下载。

  • 当前模型为英文 en_core_web_lg 和中文 zh_core_web_sm。
  • 保留既有 NLP 标签映射，忽略 ORGANIZATION 及其他排除标签。姓名和地点不等同于专门的中国 PII 模型能力，完整门牌地址需另外评测。
  • 在 zh 下注册邮箱、电话、支付卡、IBAN、IP、MAC、URL、加密货币识别器，并设置简繁中文上下文；电话区域为 CN / HK / TW。
  • 调用 analyzer.analyze(text, language)，未传类型白名单或自定义分数阈值，采用当前语言全部已注册类型及引擎默认行为。
  • PRESIDIO_TYPE_MAP 只转换输出名称，如 EMAIL_ADDRESS → email、US_SSN → us_ssn；未映射名称转小写。LOCATION 目前映射为 address，不能据此假定完整地址已被覆盖。
  • 初始化异常被记录并令此引擎不可用；检测异常被记录后返回已收集结果，通常为空。单次接口响应没有明确标注这一层是失败还是未检出。

此前实际注册表核对为英文 19 类、中文 13 类，注册状态不等于准确率。模型文件值按已安装包名使用，当前预检查不支持任意本地模型目录。类型明细见 Presidio 标签参考。

06 / GLiNER2：本地标签驱动的实体提取

gliner.py 使用 fastino/gliner2-privacy-filter-PII-multi，将文本和 ENTITY_LABELS 一起输入模型，通过上下文预测实体片段。

result = self.model.extract_entities(
    request.text, ENTITY_LABELS, threshold=GLINER_THRESHOLD,
    include_confidence=True, include_spans=True,
)
  • 当前配置 29 个标签，官方权重列出 42 个；标签列表仍写在代码中，没有逐标签配置文件。
  • 依赖缺失或模型目录不存在时，此层不可用；现有目录加载失败的异常会向外传播，可能使服务启动失败。
  • 默认阈值 0.65；结果仅接受字典中的整数 start/end，分数依次读取 confidence、score，缺失则为 0.0。
  • 适配层尚未校验跨度是否落在原文内；C# 网关另有范围检查。推理异常未捕获，会令请求失败。
  • 本地配置指向 microsoft/mdeberta-v3-base，model_type 为 extractor、max_width 为 8。后者是内部跨度设置，不是接口允许的字符数。
  • 权重约 1.23 GB，尚无系统内存、延迟或中文准确率评测。该权重的官方训练语言不含中文；中文 Presidio 测试不代表 GLiNER2 中文能力已验证。

07 / HTTP 接口、实体结构与合并

接口 / 字段行为
POST /analyze接收 text、language、include_ner，返回 entities 和 engine。
GET /health返回 status、配置开关、引擎可用状态及 presidio_languages；status=ok 不保证所有引擎可用。
text1～50,000 个 Python 字符，不是模型 token 上限。
language长度 2～8，默认 en；请求结构并非仅 en/zh 枚举，实际支持由模型决定。服务不自动选择语言。
include_ner默认 true，仅控制 GLiNER2 单次推理。

请求示例：

{
  "text": "邮箱 alice@example.com",
  "language": "zh",
  "include_ner": false
}

仅启用正则时的示意响应（默认三个引擎全开时，状态和结果可能不同）：

{
  "entities": [
    {"type": "email", "start": 3, "end": 20, "score": 0.99, "source": "rule"}
  ],
  "engine": {"rules": true, "presidio": false, "gliner": false, "offline_mode": true}
}

实体 start/end 是 Python Unicode code-point 索引，左闭右开，可用 text[start:end] 提取。source 为 rule / presidio / gliner。正常响应不额外返回敏感原文值。

编排器以 (type, start, end) 去重，完全相同的类型与位置只保留最高分，再按 start/end 排序。不同类型或不同边界的重叠结果通常保留。phone 与 phone_number、credit_card 与 card_number 等未完全统一。

正则固定分数、Presidio 规则/上下文分数及 GLiNER2 模型分数没有统一校准；直接取最高分的意义有限。无效请求通常返回 HTTP 422，未捕获的推理异常导致请求失败。

08 / 配置与部署方式

引擎开关 config.json：

{"rules": true, "presidio": true, "gliner": true}

模型配置 presidio-config.json：

{"models": {"en": "en_core_web_lg", "zh": "zh_core_web_sm"}}
  • 引擎开关必须全部提供且为 JSON 布尔值；未知字段、字符串布尔值或缺失字段校验失败。Presidio 配置只允许 en/zh 模型键，模型字典至少一项。
  • 两份配置按项目路径定位，启动时读取，不支持热更新；Presidio 配置仅在该引擎启用时读取。
  • GLINER_MODEL_PATH 默认指向项目 models 目录；环境变量覆盖为相对路径时按进程工作目录解析。
  • GLINER_THRESHOLD 默认 0.65，导入时转为 float，尚无 0～1 范围校验。
  • OFFLINE_MODE 默认 true，是报告标记，不会强制阻止网络访问。
  • 全部关闭会返回空实体列表，网关将其视为未发现 PII；模型目录下的 config.json 与服务配置用途不同。
# 在 PII-Detect-Engine 目录首次准备（需要联网）
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe install_presidio_models.py
.\.venv\Scripts\python.exe download_model.py

# 已准备好环境与模型后直接启动
.\.venv\Scripts\python.exe -m uvicorn app:app --host 127.0.0.1 --port 8000

start.ps1 是便利启动脚本，会创建环境、升级 pip、安装全部依赖并启动服务，因此包含联网步骤。install_presidio_models.py 显式安装缺失 spaCy 包，download_model.py 从 Hugging Face 显式下载 GLiNER2 快照。已完成准备时可直接使用 Uvicorn 启动本地推理。

主要依赖为 FastAPI、Uvicorn、Presidio、GLiNER2、Transformers、Hugging Face Hub、Protobuf；范围见 requirements.txt。当前未使用完整锁文件或固定 Hub revision，跨环境复现仍需版本管理。

09 / 与 C# 网关的协作

网关选择语言
→
Python 检测
→
转换 UTF-16 索引
→
策略、脱敏、外部调用

相邻项目的 PiiText.cs 支持 auto / en / zh；auto 有汉字选择 zh，否则 en，不是完整语言识别。网关对每条消息调用服务，并通过 Task.WhenAll 实现消息级并发。Python 请求语言只影响 Presidio，其他检测器仍接收原文。

Security.cs 把 Python code-point 索引转换成 C# UTF-16 索引，再提取和替换，防止 emoji、生僻字导致脱敏错位；无效范围会拒绝检测响应。网关随后处理重叠实体、风险等级、allow/redact/block、Token 映射、还原和审计。

外部模型回复返回后会再检测；当前新生成 PII 仅记录 response_flagged，不会据此再次脱敏或拦截。Python 服务本身不保存这些业务状态。

11 / 当前限制与演进方向

领域限制与建议
失败语义Presidio 降级可能与未检出表现一致，GLiNER2 则可能失败。建议增加逐请求引擎状态及必须成功的检测策略。
类型与分数别名未完全统一、来源分数未校准。建议规范类型并按业务评测优先级及阈值。
并发单文本内串行、跨消息并发、模型共享。先评测线程安全、延迟和吞吐，再引入有上限的并发或批处理。
中文质量通用小型 NER 不保证完整地址或繁体姓名表现。需建立简体、繁体、中英混合评测集。
长度与校验字符限制不同于模型窗口。需增加重叠分块、全局位置还原，以及 IP / 卡号等校验。
配置与运维尚无逐类型启停和阈值配置；Python 未实现鉴权、限流、指标或持久化。按部署需要完善访问控制、观测和版本锁定。
